# UFarm Digital EVM Contracts

UFarm is an on-chain asset management protocol for creating, operating, and upgrading managed vaults across EVM networks.

This repository contains the smart contracts, deployment modules, execution scripts, generated typings, and CI packaging flow used to run the UFarm EVM protocol. The contracts cover the protocol core registry, curator and vault proxies, vault lifecycle modules, adapter execution, cross-chain settlement, escrow accounting, oracle integration, and deployment support contracts.

## Development Toolchain

Pinned Foundation toolchain:

- Hardhat: 3.15.0
- Solidity compiler: 0.8.35
- OpenZeppelin Contracts: 5.6.1
- OpenZeppelin Contracts Upgradeable: 5.6.1
- Hardhat Mocha/Ethers toolbox: 3.0.7
- Hardhat Ignition Ethers: 3.1.6
- TypeScript: 6.0.3

Contracts are compiled for the configured EVM version in `hardhat.config.ts` and `foundry.toml`. Production and satellite deployments must target chains that support the generated bytecode, including Shanghai/Cancun opcodes such as `PUSH0`.

Core Foundation commands:

```bash
npm run compile
npm run test
npm run security
```

## Deployment

The deployment flow uses Hardhat Ignition modules and wrapper scripts. All network access goes through the `ufarm` Hardhat network, so the RPC URL, chain id, and signing key are supplied through environment variables. The accounting-chain Core deployment must not target an L2 unless the deployment includes sequencer uptime checks or an equivalent operational control for Chainlink price-feed reads.

Required environment variables:

- `UFARM_RPC_URL`: RPC endpoint for the target chain.
- `UFARM_CHAIN_ID`: numeric chain id for the target chain.
- `UFARM_PRIVATE_KEY`: deployer private key used by deployment scripts.

Optional environment variables:

- `ETHERSCAN_API_KEY`: API key used by `npm run verify`.
- `PK_UFARM_OWNER`: owner private key used by upgrade and administration scripts.
- `PK_VAULT_OWNER`: vault owner private key used by vault execution scripts.
- `PK_INVESTOR`: investor private key used by investor execution scripts.

### Foundation Deployment

Use `deploy:foundation` for deterministic production-style deployment through CreateX Create3. The script derives one guarded CreateX salt from the deployer address and a 32-byte logical salt, then the Foundation module uses that salt for the Core proxy.

```bash
UFARM_RPC_URL=https://rpc.example \
UFARM_CHAIN_ID=1 \
UFARM_PRIVATE_KEY=0x... \
npm run deploy:foundation -- \
  --foundation \
  --core-config \
  --adapters \
  --timelock \
  --parameters ./ignition/parameters/mainnet.json \
  --deployment-id foundation-mainnet
```

Module flags:

- `--foundation`: deploy Core, Escrow, Quex Oracle, Curator beacon, Vault beacon, and base Foundation contracts.
- `--core-config`: apply Core value token, oracle, and related protocol configuration.
- `--adapters`: deploy and register vault adapters.
- `--timelock`: transfer Core authority and beacon ownership to the configured timelock.

Parameter options:

- `--parameters <path>`: Ignition parameters JSON file.
- `--no-parameters`: use module defaults where allowed.
- `--deployment-id <id>`: Ignition deployment id.
- `--logical-salt <bytes32>`: 32-byte logical salt. Defaults to `keccak256("UFARM_FOUNDATION")`.
- `--dry-run`: print deployment details without calling `ignition.deploy`.

When deploying only a later module, the required addresses must be present in the parameters file. For example, `--core-config` and `--adapters` need `core`, while `--timelock` also needs the curator and vault beacon addresses.

### Post-deployment Quex Configuration

After deploying the Foundation and Core configuration modules, configure the Quex oracle action data before accepting vault deposits. Use the Quex configuration execution script with deployment-specific request parameters:

```bash
npm run exec:oracle:configure-quex -- \
  --oracle 0xOracleAddress \
  --request-oracle-pool 0xRequestOraclePool \
  --config ./scripts/quex-request.sample.json
```

Vault settlement through `UFarmQuexOracle` remains unavailable until this configuration succeeds.

### Private Test Setup

Use `deploy:private-setup` for local or private-chain smoke deployments. It deploys local helper contracts such as CreateX, Quex mocks, CCIP router mock, and a value token, then deploys and configures the Foundation modules against those helpers.

```bash
UFARM_RPC_URL=http://127.0.0.1:8545 \
UFARM_CHAIN_ID=31337 \
UFARM_PRIVATE_KEY=0x... \
npm run deploy:private-setup -- \
  --parameters ./ignition/parameters/private.json \
  --private-setup-deployment-id private-setup \
  --foundation-deployment-id foundation-test
```

Options:

- `--parameters <path>`: optional Ignition parameters JSON file.
- `--private-setup-deployment-id <id>`: deployment id for private helper contracts. Defaults to `private-setup`.
- `--foundation-deployment-id <id>`: deployment id for Foundation contracts. Defaults to `foundation-test`.
- `--dry-run`: print deployment details without calling `ignition.deploy`.

### Upgrades

Use `upgrade:foundation` to compare compiled bytecode with currently deployed implementations and deploy only changed implementations.

```bash
UFARM_RPC_URL=https://rpc.example \
UFARM_CHAIN_ID=1 \
PK_UFARM_OWNER=0x... \
npm run upgrade:foundation -- \
  --core 0xCoreAddress \
  --include core,escrow,oracle,curator,vault,guard,adapters
```

Required:

- `--core <address>`: deployed `UFarmCore` proxy address.
- `PK_UFARM_OWNER`: private key with permission to perform the requested upgrades.

Options:

- `--include <list>`: comma-separated targets. Supported targets are `core`, `escrow`, `oracle`, `curator`, `vault`, `guard`, and `adapters`.
- `--guard <address>`: override the arbitrary adapter guard address.
- `--dry-run`: compare bytecode and print planned actions without deploying or sending upgrade transactions.

### Verification

Verify contracts with Hardhat using the same `ufarm` network:

```bash
UFARM_RPC_URL=https://rpc.example \
UFARM_CHAIN_ID=1 \
UFARM_PRIVATE_KEY=0x... \
ETHERSCAN_API_KEY=... \
npm run verify
```

Ignition deployments can be verified with:

```bash
UFARM_RPC_URL=https://rpc.example \
UFARM_CHAIN_ID=1 \
UFARM_PRIVATE_KEY=0x... \
ETHERSCAN_API_KEY=... \
npm run verify:ignition
```
